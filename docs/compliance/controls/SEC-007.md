## Requirement
Defence in depth on every API call: transport, identity, authorisation, input and abuse control.
Gate E2 acceptance: the OWASP API Top 10 checklist is reviewed with no open High findings.

## How MoDocument meets it today
- **Transport.** TLS 1.2+ only at the edge: CloudFront `TLSv1.2_2021`, ALB
  `ELBSecurityPolicy-TLS13-1-2-2021-06`, HTTP redirected to HTTPS (`infra/terraform/modules/edge/main.tf`,
  `infra/terraform/modules/ecs-app/main.tf`); HSTS one year. The app port is not published; the
  database requires TLS (`verify-full` on AWS). Optional mutual TLS for bank systems on a separate
  `api.<domain>` listener (`infra/terraform/modules/ecs-app/mtls.tf`).
- **Identity — users.** MoDocument-issued HS256 JWT, 15 minutes, revocable (jti denylist,
  `TokenVersion`), MFA for administrators (`src/main/java/com/modocument/api/config/SecurityConfig.java`;
  SUP-S02, SEC-014).
- **Identity — machines.** OAuth2 client credentials (`POST /api/integration/oauth/token`,
  RFC 6749; client tokens 15 minutes, optionally certificate-bound per RFC 8705), API key
  (`Authorization: ApiKey <prefix>.<secret>`, Argon2id-hashed secret) or a client certificate
  forwarded only by the trusted proxy. Per-bank switches decide which methods are allowed; every
  client has scopes, an optional IP allow-list, an expiry and immediate revocation
  (`src/main/java/com/modocument/infrastructure/security/client/ApiClientAuthenticator.java`,
  `src/main/java/com/modocument/infrastructure/security/client/ClientAuthenticationFilter.java`,
  `src/main/java/com/modocument/infrastructure/security/client/MtlsClientCertificates.java`).
  User tokens and machine credentials never cross: machine paths admit only API clients, every
  other path only users.
- **Authorisation.** One `@RequiresPermission` per handler, deny by default
  (`RoutePermissionCoverageTest`); bank isolation by PostgreSQL row-level security plus app-level
  scoping; another user's or bank's object answers 404 (`CrossUserAccessTest`); client scopes
  narrow further (`src/main/java/com/modocument/api/security/PermissionChecker.java`).
- **Input.** Bean Validation on request DTOs; integration API body cap 10 MB, at most 10,000 records
  and 25 MB per file (`src/main/resources/application.yml`); upload content gate (SUP-S01); SQL
  identifiers allow-listed and no free SQL in connectors; egress (SSRF) guard on outbound calls
  (`docs/qa/integration-security-tests.md` §1–2).
- **Abuse control.** Per-user buckets on expensive endpoints, sign-in and MFA throttles,
  600 requests per minute per API client, 120 token requests per address, 60 Argon2id
  verifications per address per 15 minutes; `429` with `Retry-After`
  (`src/main/java/com/modocument/infrastructure/ratelimit/ApiRateLimitInterceptor.java`);
  AWS WAF rate-based rules at the edge (`infra/terraform/modules/edge/main.tf`).
- **Idempotency.** Every integration POST needs an `Idempotency-Key`; a replay returns the same
  job, a reuse with another body is 409; keys live 24 hours
  (`src/main/java/com/modocument/infrastructure/integration/IdempotencyStore.java`).
- **Webhook signatures.** Outbound webhooks carry `X-MoDocument-Timestamp` and
  `X-MoDocument-Signature: sha256=HMAC-SHA256(secret, timestamp + "." + body)`; the receiver
  refuses a timestamp older than 5 minutes and compares in constant time. Verification sample:
  `WebhookSigner.verify` (`connector-core/src/main/java/com/modocument/connector/core/webhook/WebhookSigner.java`)
  and the developer guide §6 (`docs/integration/developer-guide.md`).
- **Security test plan** with 49 cases (S1–S49) and its coverage map: 48 pass at an automated level,
  S28 (optional API-key request signing) is a recorded gap (`docs/qa/integration-security-tests.md`).
- **OWASP API Top 10 checklist:** `docs/security/owasp-api-top10.md`.

## Questionnaire answer (final)
Yes. Every API call to MoDocument is protected in layers. Traffic is encrypted with TLS 1.2 or
1.3 only. Every call must be authenticated: people use short-lived, revocable tokens issued by
MoDocument (with MFA for administrators); bank systems use OAuth 2.0 client credentials, an API key
or mutual TLS, each with limited scopes, an optional IP allow-list, an expiry and immediate
revocation. Each operation checks the caller's permission, and every query is limited to the
caller's own bank by database row-level security. Inputs are validated and size-limited, calls are
rate-limited per user and per client, write calls from bank systems are idempotent, and the webhooks
MoDocument sends are signed with HMAC-SHA256 and a timestamp so the bank can reject forgeries and
replays. Evidence: SEC-007-E01.

## Risk R-SEC-007
Broken object-level authorisation or unthrottled endpoints leak data at machine speed. Cause in
the workbook: authentication solid but object-level checks inconsistent. Object-level checks are
enforced in the app and by row-level security and tested; throttling is per instance plus WAF.
Likelihood, impact and residual are set in MO-031.
