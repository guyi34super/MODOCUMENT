## Requirement
Retain audit and security logs for 7 years, affordably, immutably and
searchably enough. Acceptance: a 13-month-old log line is retrievable via
the documented procedure (Go-Live Security Gate item A15 in the workbook's
numbering).

## How MoDocument meets it today
Full source-by-source table:
[log-retention-and-rehydration.md](../policies/log-retention-and-rehydration.md) §1.
Pre-production; Terraform validated, not deployed.

- **7-year WORM archive exists in code:** S3 bucket with Object Lock
  enabled at creation, versioning, public access blocked, SSE-KMS;
  default retention COMPLIANCE 7 years when `enforce_backup_locks = true`;
  lifecycle to Glacier after 90 days and expiry after 2557 days
  (`infra/terraform/modules/backups/main.tf`, TF-44 to TF-46). The lock is
  off by default (`infra/terraform/envs/production/variables.tf`).
- **What goes into it:** CloudTrail (multi-region, log-file validation)
  and Session Manager session logs (`infra/terraform/modules/security-monitoring/main.tf`,
  TF-93, TF-97). CloudTrail is also kept 400 days hot in CloudWatch; code
  refuses less than 365 (TF-94).
- **Application audit trail:** `AuditEvent` is append-only in the database
  (privileges revoked and triggers) and never purged by the application
  (`src/main/resources/db/migration/V14__audit_event.sql`;
  `src/test/java/com/modocument/pgit/AuditAppendOnlyPgIT.java`;
  `src/main/java/com/modocument/infrastructure/retention/RetentionPurger.java`
  does not touch it; `docs/security/retention-and-dsr.md`). It has **no
  copy in the archive**: database backups reach back 90 days only.
- **Not archived:** app/nginx logs (90 days), flow logs (30 days),
  PostgreSQL logs (retention not set), and no WAF/ALB/CloudFront logs at
  all (DEF-5, DEF-6, DEF-9). `docs/security/data-inventory.md` rows 14–15
  overstate the archive (DOC-3).
- **Rehydration runbook written:** [log-retention-and-rehydration.md](../policies/log-retention-and-rehydration.md)
  §3, with the test note template (§4). Never run.

## Questionnaire answer (final)
MoDocument is not yet in production. Its infrastructure code creates a log
archive in Amazon S3 with Object Lock in compliance mode and a seven-year
retention, moving logs to Glacier after 90 days; AWS CloudTrail writes all
account activity there with integrity validation, and the lock is enabled
in production once our restore drill has passed. The application's audit
trail is append-only in the database and is never deleted by the
application. Before go-live we are adding a daily export of the audit
trail and the shipping of application and database logs into the same
locked archive; application logs are kept 90 days. A documented procedure
retrieves archived log lines, and it will be tested yearly. Evidence:
SEC-033-E01.

## Test SEC-033-T01
- **Procedure:** (1) static: list every log source and check its
  retention and archive path in code; validate Terraform; (2) acceptance:
  run the rehydration runbook on a 13-month-old log line.
- **Expected result:** a 13-month-old log line is retrievable via the
  documented procedure.
- **Actual result:** (1) only CloudTrail and session logs reach the
  7-year archive, and only once locks are enforced; the audit trail and
  application logs are not archived; validate passed; (2) not possible —
  no archive exists, and no 13-month-old log can exist before November
  2027.
- **Result:** Partial.
- **Tester:** Agent A8 (static re-performance); human sign-off required.
- **Date:** 2026-10-19.

## Risk R-SEC-033
- **Risk:** evidence needed for a dispute or investigation has rotated
  away.
- **Cause:** short retention everywhere except CloudTrail; the audit trail
  has no archived copy.
- **Mitigation:** archive pipeline into the locked bucket, lock enforced,
  yearly rehydration test. Likelihood, impact and residual are set in
  MO-031.
