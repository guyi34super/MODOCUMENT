## Requirement
Ship structured, normalised security events to any bank's SIEM in near real
time. Acceptance: a login-failure event appears in the reference SIEM less
than 60 s after it happens.

## How MoDocument meets it today
The owner statement of 2 Oct 2026 said the event format was not documented
and tenant scoping of the feed was unknown. Both are now answered by the
repository.

- **Event format documented:** `docs/security/siem-event-schema.md` — one
  JSON document per audit row, Elastic Common Schema 8.11 names plus a
  `modocument.*` namespace; field-stability promise. The field table is
  pinned to the only serializer
  (`src/main/java/com/modocument/infrastructure/siem/SiemEventMapper.java`)
  by `SiemFeedE6Test`, so the document cannot drift from the output.
- **Tenant scoping proven:** the pull feed `GET /api/siem/events`
  (`src/main/java/com/modocument/api/controller/SiemFeedController.java`,
  permission `siem:read`, ADMIN only) takes the bank from the caller's token
  and filters by it, and PostgreSQL RLS filters again. `SiemFeedE6Test` seeds
  two banks and proves each feed holds only its own events. The push
  forwarder (`src/main/java/com/modocument/infrastructure/siem/SiemWebhookForwarder.java`)
  serves exactly one configured bank and drops every other bank's events.
  The workbook's warning "do not offer the feed to MauBank before scoping is
  confirmed" is answered by this test; the decision to offer it stays with
  the owner.
- **Transports:** HTTPS pull feed with cursor paging (NDJSON); optional HTTPS
  push in NDJSON batches with an HMAC-SHA256 signature; structured ECS JSON
  application logs (`structured-logs` profile,
  `src/main/resources/application.yml`). Configuration keys:
  `modocument.siem.*` (`src/main/resources/application.yml`; compose
  variables in `docker-compose.yml`). **Syslog over TLS and CEF are not
  built.**
- **Not yet done:** no reference-SIEM ingestion test; the ECS task
  definition does not set the `structured-logs` profile or the SIEM push
  variables (`infra/terraform/modules/ecs-app/main.tf`).

## Questionnaire answer (final)
Every security event is recorded once, in an append-only audit trail, and
exported to the bank's SIEM as structured JSON using Elastic Common Schema
field names, with a published field reference and a field-stability promise.
A bank's SIEM can pull its events over HTTPS with cursor-based paging, or
receive them by signed HTTPS push. Each bank's feed contains only that bank's
events: this is enforced by the bank identity in the access token and by
database row-level security, and verified by an automated two-bank test. An
end-to-end validation with a reference SIEM (Elastic or Splunk) is scheduled
for 30 November 2026. Syslog and CEF delivery are not offered today.
Evidence SEC-031-E01.

## Test SEC-031-T01
- **Procedure:** run a reference SIEM (free Elastic or Splunk), point it at
  the pull feed of a test bank, cause one failed login, measure the time
  until the `LOGIN_FAILED` event is searchable.
- **Expected result:** a login-failure event appears in the reference SIEM
  less than 60 s after it happens.
- **Actual result:** not performed — no reference SIEM is available in the
  repository or the sandbox. What was run instead: `SiemFeedE6Test` (6 tests
  pass): bank-scoped feed, cursor paging without gaps or repeats, ADMIN-only
  access, single-bank push delivery to a test receiver, schema document =
  serializer output. Design latency with the default settings (5 s settle +
  a 15 s poll interval) is about 20 s; not measured.
- **Result:** Not run · tester: Agent A5 (automated re-performance; human
  sign-off required) · date: 2026-10-19.

## Risk R-SEC-031
The bank is blind to events inside the platform that affect its data; or a
bank's feed carries another bank's events. Cause: export built before
documentation and a reference test. Mitigation: documented and pinned
schema; tested bank scoping; reference-SIEM test. Likelihood, impact and
residual are set in MO-031 (both workbook risk rows).
