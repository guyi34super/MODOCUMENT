## Requirement
Publish a complete, versioned API catalogue with machine-readable specifications. Gate E2
acceptance: a new integrator can call the sandbox using only the documents.

## How MoDocument meets it today
| API type | Base path | Authentication | Documentation |
|---|---|---|---|
| REST/JSON user API (the web app's own API) | `/api/**` and legacy CRUD paths (`/Templates/**`, …) | Bearer JWT issued by MoDocument | OpenAPI at `/v3/api-docs` |
| Integration API v1 for bank systems | `/api/integration/v1/**` (+ `POST /api/integration/oauth/token`) | OAuth2 client credentials, API key or mutual TLS | `docs/integration/developer-guide.md`, Postman collection |
| Connector Agent protocol v1 | `/api/agent/v1/**` | Agent API client (enrolled with a one-time token) | `docs/integration/agent.md` |
| Outbound webhooks (MoDocument → bank) | bank-defined URL | HMAC-SHA256 signature + timestamp | developer guide §6 |
| Outbound connectors (REST, database, SFTP) | bank systems | per connection, secrets sealed | `docs/integration/connector-sharing.md` |
| SIEM feed | `GET /api/siem/events` (NDJSON) | Bearer JWT, `SIEM_READ` | `docs/security/siem-event-schema.md` |

- **Machine-readable spec:** springdoc generates OpenAPI 3.1 from the code
  (`src/main/java/com/modocument/api/config/OpenApiConfig.java`, `pom.xml`); the 245-route
  inventory is pinned in `docs/api/openapi-routes.txt` and checked by `OpenApiContractTest` in every
  build (spec well-formed, every handler in the spec and nothing else, inventory identical,
  anonymous routes exactly the agreed list, 429 documented, stable `operationId`s).
- **Exposure:** `/v3/api-docs` needs a valid token outside dev (`ApiDocsExposureTest`); Swagger UI
  only in the `local` profile (`src/main/resources/application.yml`).
- **Versioning and deprecation policy:** additive vs breaking rules, `/v2` for breaking changes,
  6-month deprecation with `Deprecation`/`Sunset` headers driven by `@DeprecatedEndpoint`
  (`docs/api/versioning-policy.md`, `src/main/java/com/modocument/api/config/DeprecationHeaderInterceptor.java`,
  `DeprecatedEndpointsTest`). 20 routes are deprecated with sunset 2027-04-01.
- **Sandbox credentials process:** defined in
  [api-sandbox-access-process.md](../policies/api-sandbox-access-process.md); the sandbox itself is
  not deployed.

## Questionnaire answer (final)
MoDocument exposes REST APIs with JSON payloads, described by an OpenAPI 3.1 specification that is
generated from the code and checked automatically on every build. There are three API families:
the user API behind the web application (bearer tokens), a versioned integration API for bank
systems (`/api/integration/v1`, with OAuth 2.0 client credentials, API keys or mutual TLS), and a
versioned protocol for the optional on-premises Connector Agent (`/api/agent/v1`). MoDocument can
also call the bank's systems through REST, database and SFTP connectors, and sends signed webhooks
(HMAC-SHA256). A written versioning policy keeps a published path stable within a version and gives
at least six months' notice before a route is removed. A sandbox access process is defined; the
sandbox environment is set up before the first external integrator starts. Evidence: SEC-006-E01.

## Risk R-SEC-006
Shadow interfaces exist without security review, and integrators guess and mis-integrate. Cause in
the workbook: the OpenAPI spec drifts from the implementation. The generated spec and the pinned
route inventory remove the drift cause while CI runs. Likelihood, impact and residual are set in
MO-031.
