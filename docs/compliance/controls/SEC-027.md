## Questionnaire answer (final)
MoDocument's security features are listed in one catalogue, organised by identity and authentication, authorization and dual control, tenant isolation and data protection, audit and monitoring, configuration guardrails, integration security, AI controls, document creation and the delivery pipeline. Each feature names the code that implements it and the automated test that proves it; on 19 Oct 2026 every one of the 106 file references and 95 test classes named in the catalogue was checked to exist, and the tests behind the main controls were re-run green. Highlights: individual accounts with MFA and lockout, six roles with every API route mapped to a permission, maker/checker on 17 kinds of sensitive change, database-enforced tenant isolation, PII masking per role and channel, an append-only audit trail with a viewer, AES-256-GCM encryption of stored secrets with per-bank keys, TLS everywhere at the edge and to the database, and an AI gateway that pseudonymises prompts and keeps each prompt to one bank. Infrastructure controls are written as code and will be applied at go-live; the catalogue marks them and lists the open gaps (evidence SEC-027-E01).
