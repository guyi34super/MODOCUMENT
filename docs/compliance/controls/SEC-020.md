## Requirement
Password recovery is cryptographically impossible; only resets exist. Gate B2 acceptance: a DBA
with full read access cannot authenticate as any user (demonstrated in a test with a dumped table).

## How MoDocument meets it today
- **Hash-only schema.** User passwords are stored only as Argon2id hashes in
  `AppUsers.PasswordHash` (`src/main/resources/db/migration/V1__baseline_schema.sql`,
  `src/main/resources/db/migration/V40__ws06_password_hash_and_lockout.sql`). Recovery codes,
  refresh tokens, API client secrets and agent enrolment tokens are also hash-only
  (`src/main/resources/db/migration/V41__ws06_mfa_tables.sql`,
  `src/main/resources/db/migration/V15__refresh_and_revoked_tokens.sql`,
  `src/main/resources/db/migration/V260__ws26_machine_identity.sql`,
  `src/main/resources/db/migration/V261__ws26_integration_agents.sql`). The TOTP secret is
  AES-256-GCM encrypted with a key held outside the database. Full column list:
  [credential-storage-and-reset-design.md](../policies/credential-storage-and-reset-design.md).
- **No admin view.** `UserDto` and `AdminUserDto` carry no password or hash; pending changes strip
  `passwordHash` from every response (`src/main/java/com/modocument/application/dto/AdminUserDto.java`,
  `src/main/java/com/modocument/application/usecase/PendingChangeUseCase.java`).
- **Resets only.** An administrator can request a temporary password for another user under
  maker/checker; only its hash is kept, all sessions end, and the user must choose a new password
  before doing anything else (`src/main/java/com/modocument/application/usecase/UserPasswordResetChangeApplier.java`,
  `src/main/java/com/modocument/infrastructure/security/PasswordChangeRequiredGate.java`).
- **Identity-provider accounts** (Entra ID, Keycloak) have an unusable random hash in MoDocument
  and are reset in the provider (`docs/security/identity-providers.md`).

## Questionnaire answer (final)
No. MoDocument never stores a password in readable form: only a salted Argon2id hash is kept, and
no screen, API or report shows a password or its hash. Passwords cannot be recovered, only reset.
A reset is requested by one bank administrator and approved by a second; it sets a temporary
password that the user must change at first sign-in, and it ends all of the user's existing
sessions. Users who sign in through Microsoft Entra ID or Keycloak have no MoDocument password at
all. Evidence: SEC-020-E01.

## Risk R-SEC-020
Insider impersonation of users without trace. Cause in the workbook: support can see or set known
passwords. Today nobody can see a password; an administrator can set a temporary one only with a
second approver, and the action is audited (`USER_PASSWORD_RESET`). Likelihood, impact and
residual are set in MO-031.
