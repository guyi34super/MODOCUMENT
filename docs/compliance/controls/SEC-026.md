# SEC-026 — Patch, database and OS update process

| Workbook | Area | Priority | Status (repo-verified) | Evidence ID | Test ID | Risk ID |
|---|---|---|---|---|---|---|
| 04 IT Infrastructure | IT Infrastructure & Operations | P1 | Partially Implemented | SEC-026-E01 | SEC-026-T01 | R-SEC-026 |

## Requirement
A predictable patch cadence with an emergency path, covering OS, database,
runtime, dependencies and images. Acceptance: a scan shows no missing
critical patches older than the SLA.

## How MoDocument meets it today
- **Policy written (proposed):**
  [patch-management-policy.md](../policies/patch-management-policy.md) —
  who patches each layer, time limits, monthly cycle, emergency-patch
  runbook, monthly report template.
- **Dependencies, actions, base images, Terraform providers:** Dependabot
  weekly across Maven, npm, GitHub Actions, Docker and Terraform, with a
  7-day cooldown for version updates and immediate security updates
  (`.github/dependabot.yml`).
- **Images:** weekly rebuild from current base tags with Trivy scan and an
  automatic tracking issue (`.github/workflows/image-rebuild.yml`); the
  release pipeline fails on fixable HIGH/CRITICAL findings
  (`.github/workflows/release.yml`). Critical limit: 72 hours
  (`docs/release/runbook.md` §6).
- **Database engine:** RDS minor versions upgraded automatically in the
  Sunday 03:00–04:00 UTC maintenance window
  (`infra/terraform/modules/rds/main.tf`, TF-26); majors through
  Terraform. DEF-13: the minor-version pin will fight the automatic
  upgrades.
- **Node OS and ECS agent:** AWS ECS-optimised AMI resolved at plan time;
  nodes are replaced only by a manual instance refresh
  (`infra/terraform/modules/ecs-app/main.tf`, TF-60, TF-62, DEF-10).
- **The process is not meeting its own limit.** The first weekly rebuild
  (2026-10-12) found **11 fixable CRITICAL** findings in the app image
  (Tomcat embed 10.1.42, Spring Security Web 6.5.1, Spring WebMVC/WebFlux
  6.2.8) and opened issue #52; on 2026-10-19 the issue is still open and
  `pom.xml` still declares Spring Boot 3.5.3 — 7 days, beyond the 72-hour
  limit. The 2026-10-19 rebuild **did not run**: GitHub refused to start
  the job because of a billing or spending-limit problem. Details and
  commands: [A8-patch-report-2026-10.md](../evidence/A8-patch-report-2026-10.md).
  There is no production, so there is no live exposure.
- **Time limit conflict:** the 2 Oct 2026 design says critical fixes
  within 24 hours; the runbook says 72 hours. `TO CONFIRM
  (organisational)`.

## Questionnaire answer (final)
MoDocument's application dependencies, container base images, CI actions
and infrastructure providers are checked weekly by GitHub Dependabot, and
both container images are rebuilt and vulnerability-scanned every week;
a release cannot ship with a fixable high or critical finding. AWS patches
the managed layers (RDS engine minor versions in our Sunday maintenance
window, load balancer, CloudFront); we refresh the ECS server images and
our container images. Routine patches follow a monthly cycle and critical
fixes have an emergency path with a 72-hour limit. MoDocument is
pre-production; our first weekly scan (12 October 2026) found critical
issues in web-framework dependencies, which are tracked for a patch
release (owner Bhavish Nobeen, proposed date 22 October 2026). The monthly
patch report starts with October 2026. Evidence: SEC-026-E01.

## Test SEC-026-T01
- **Procedure:** read the latest weekly scan results (issue "Security: base
  image refresh") and the current `pom.xml`; compare the age of each fixable
  CRITICAL with the 72-hour limit; check the scheduled runs happened.
- **Expected result:** scan shows no missing critical patches older than
  the SLA.
- **Actual result:** 11 fixable CRITICAL findings from 2026-10-12 still
  unpatched on 2026-10-19 (7 days); the 2026-10-19 scheduled scan did not
  start (GitHub billing). Node and database layers cannot be checked (no
  AWS).
- **Result:** Fail.
- **Tester:** Agent A8 (re-performance); human sign-off required.
- **Date:** 2026-10-19.

## Risk R-SEC-026
- **Risk:** known-exploited vulnerabilities remain open for months.
- **Cause:** application dependencies patched but OS/DB forgotten; or, as
  observed, findings raised but not shipped within the limit.
- **Mitigation:** weekly scans with a failing run while a CRITICAL is open,
  release gate, monthly report reviewed by the owner, emergency runbook.
  Likelihood, impact and residual are set in MO-031.
