## Requirement
Complete, correlatable logging across user, admin, system, API and data layers. Given any audit event, the surrounding API call, session and infrastructure context are findable by correlation ID (gate E9).

## How MoDocument meets it today

Inside the application, one request id ties the HTTP response, every log line and every audit row together, and this is proven by a test. Outside the application (edge, load balancer, nginx, agent) the id is not logged, and the cloud log stack is Terraform only.

### Correlation keys
`RequestIdFilter` honours a safe inbound `X-Request-Id` (`[A-Za-z0-9-]{1,64}`) or mints a UUIDv7, puts it on the logging MDC with the client IP, echoes it in the response header and in every error body, and the audit recorder stamps it on the `AuditEvent` row. `IdentityContextFilter` adds `userId` and `role`, `TenantContext` adds `bankId`; `TenantTaskDecorator` copies them onto async threads. The audit row also carries `SessionJti` (the access token's id). Proof: `src/main/java/com/modocument/infrastructure/security/RequestIdFilter.java`, `src/main/java/com/modocument/infrastructure/security/IdentityContextFilter.java`, `src/main/java/com/modocument/infrastructure/async/TenantTaskDecorator.java`, `src/main/java/com/modocument/infrastructure/audit/JpaAuditRecorder.java`, `src/main/java/com/modocument/api/controller/ApiExceptionHandler.java`, `src/main/resources/db/migration/V14__audit_event.sql`.

### Cross-service trace for one request id (how)

Proven in a test, not in a live screenshot (nothing is deployed). `RequestTraceabilityE9Test#oneActionCarriesTheSameRequestIdUserAndBankEverywhere` sends `PUT /Templates/Update` with `X-Request-Id: e9-trace-<uuid>` and asserts: (1) the response echoes the id; (2) a log line of the request carries the same `requestId`, `userId` and `bankId`; (3) the `TEMPLATE_UPDATED` audit row carries the same request id, actor, role, bank, entity, old and new values, outcome and the session jti. A second test proves a refused call is audited with the path and the same id; a third that an unsafe inbound id is replaced. Run R1 on 2026-10-19: 3 tests, 0 failures.

In production the same trace is two queries: CloudWatch Logs Insights over the app log group, `filter @message like "<requestId>"` (or `filter requestId = "<requestId>"` with the `structured-logs` profile), and `SELECT … FROM AuditEvent WHERE RequestId = '<requestId>'` (or the audit viewer filtered by entity, actor and time). The CloudTrail role session name ties a deploy to its GitHub run.

## Questionnaire answer (final)
Every request to MoDocument gets one request ID (taken from the caller when it is safe, otherwise generated). The ID is returned in the response, printed on every application log line together with the user and the bank, included in error messages, and stored on every audit record together with the user, role, bank, session, IP address and the old and new values. Authentication, user actions, administrative and configuration changes, access refusals, machine API calls, background jobs, AI calls and deployments are all recorded in the append-only audit trail, so one search by request ID reconstructs what a user did and what changed; an automated test proves this end to end. Infrastructure activity is captured by AWS CloudTrail, VPC flow logs and GuardDuty, defined as code for go-live. Before go-live we will add the request ID to the web-server and load-balancer logs and switch on structured JSON logging in the cloud deployment (evidence SEC-034-E01).

- **Procedure:** Re-run `RequestTraceabilityE9Test`, `JpaAuditRecorderTest`, `LogRedactionCanaryTest` and `StructuredLogRedactionTest` (run R1). Inspect the edge, ALB, nginx, ECS and agent configuration for request-id logging.
- **Expected result:** one request id links response, log lines and audit row; every layer logs it.
- **Actual result:** 14 tests, 0 failures (`JpaAuditRecorderTest` 8, `RequestTraceabilityE9Test` 3, `StructuredLogRedactionTest` 2, `LogRedactionCanaryTest` 1). Not correlated: CloudFront/WAF and ALB (no access logs configured), nginx (default log format without the id), Connector Agent (sends no id).
