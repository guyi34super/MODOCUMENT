## Requirement
Establish a vulnerability management cycle and obtain an independent
penetration test. Acceptance: no open Critical/High findings at submission;
share summaries, keep full technical reports controlled.

## How MoDocument meets it today
The owner statement of 2 Oct 2026 said "no vulnerability scanning ever".
That is out of date: scanning is configured in CI and was run for this pack.

- **Configured scans:** gitleaks over full history, Semgrep (registry packs
  + `.semgrep/modocument.yml`), dependency review and `npm audit
  --audit-level=high` on every push/PR and weekly
  (`.github/workflows/security.yml`); weekly image rebuild + Trivy with an
  auto-opened issue (`.github/workflows/image-rebuild.yml`); weekly OWASP ZAP
  baseline (`.github/workflows/zap-baseline.yml`, `.zap/rules.tsv`); SBOM per
  release (`.github/workflows/sbom.yml`); Dependabot weekly
  (`.github/dependabot.yml`).
- **SLAs:** Critical ≤ 72 h, High ≤ 14 d, Medium ≤ 30 d (workbook); 72 h
  patch release for a critical CVE (`docs/release/runbook.md` §6).
- **Latest report:** `docs/compliance/evidence/A5-vulnerability-assessment-report-2026-10.md`
  (2026-10-19): secrets 0, SAST (repo rules) 0, npm 0, ZAP 0 fail / 1 low
  warning, **Trivy (2026-10-12): 11 critical + 41 high fixable library
  vulnerabilities in the app image, still present in the current `pom.xml`**.

  and image-rebuild workflows fails within seconds (no runner assigned).
- **Penetration test:** none ever (owner statement; nothing in the
