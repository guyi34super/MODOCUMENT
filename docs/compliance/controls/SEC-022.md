## Requirement
Support TOTP and time-limited one-time codes wherever a code is issued. Gate B3/B4 acceptance: an
expired OTP and a replayed TOTP code both fail in test.

## How MoDocument meets it today
- **TOTP (RFC 6238)** is built in: 6 digits, 30-second step, ±1 step of clock skew, HMAC-SHA1
  (`src/main/java/com/modocument/infrastructure/security/totp/Totp.java`). The per-user secret is
  160-bit random and stored AES-256-GCM encrypted (`src/main/java/com/modocument/infrastructure/security/MfaSecretCipher.java`,
  `src/main/resources/db/migration/V41__ws06_mfa_tables.sql`).
- **Replay prevention:** the last accepted step is stored (`LastUsedCounter`); the same or an
  older step never verifies again (`src/main/java/com/modocument/application/usecase/MfaUseCase.java`).
- **Attempt limits:** 5 TOTP attempts per user and 30 per address per minute
  (`src/main/java/com/modocument/infrastructure/ratelimit/MfaRateLimiter.java`).
- **Expiring codes and tokens:** MFA challenge 5 minutes, access token 15 minutes, refresh idle
  12 hours and absolute 7 days, agent enrolment token 15 minutes, API client initial secret 24
  hours, webhook signature 5-minute replay window.
- **Recovery codes:** 10 single-use codes, Argon2id-hashed.
- **Keycloak path:** realm TOTP 6 digits / 30 s, look-ahead window 1, OTP enrolment is a default
  required action (`docker/keycloak/modocument-realm.json`). Entra ID OTP settings live in the
  tenant (`TO CONFIRM (organisational)`).
- **Not used:** e-mail or SMS OTPs and password-reset links do not exist. Resets are
  admin-issued temporary passwords under maker/checker.

| Type | Length | TTL | Attempts | Replay |

## Questionnaire answer (final)
Yes. MoDocument has built-in time-based one-time passwords (TOTP, RFC 6238: 6 digits, 30-second
step, one step of clock tolerance). An accepted code can never be used again, and code checks are
rate-limited per user and per network address. Every other code or token MoDocument issues has a
fixed lifetime: the MFA sign-in challenge expires after 5 minutes, access tokens after 15 minutes,
sessions after 12 hours idle or 7 days at most, and one-time enrolment tokens after 15 minutes.
MoDocument does not send e-mail or SMS codes or password-reset links. Bank users who sign in through
Microsoft Entra ID or Keycloak receive their one-time codes from that provider. Evidence:
SEC-022-E01.

## Risk R-SEC-022
A stolen reset link or OTP works days later. Cause in the workbook: reset tokens never expire.
MoDocument has no reset links; the remaining exposure is the non-expiring temporary password.
Likelihood, impact and residual are set in MO-031.
