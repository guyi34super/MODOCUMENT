## Questionnaire answer (final)

MoDocument has a documented stress test plan and a stress testing report. The test was run on
19 October 2026 with synthetic data only, on a pre-production test environment (one
application instance, production configuration with row-level security, a 4-vCPU machine,
plus a run pinned to one CPU to approximate one production task). It covered concurrent data
entry, concurrent report generation, large templates (300-field PDF forms, 50,000-row files),
a peak user mix at 1×, 2× and 4× an assumed peak of 50 concurrent users, a 10-minute soak,
overload behaviour (rate limits, AI outage, database pool saturation) and a breakpoint search.
Results: 0 errors at 1× and 2× peak with p95 latency below 60 ms for interactive requests; one
instance on 4 CPUs sustained about 715 requests per second within the latency thresholds and
reached its latency breaking point at 400 concurrent fast-clicking users, with no errors; the
machine's CPU was the bottleneck. Nine findings (none critical) have owners and dates. Raw
outputs are archived with the report. Before go-live the same plan is re-run on the staging
environment at 2× the confirmed peak, and the report is re-issued at least every 12 months and
after major architecture changes. Evidence: SEC-008-E01.
