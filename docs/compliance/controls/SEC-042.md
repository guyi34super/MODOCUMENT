## Questionnaire answer (final)
MoDocument keeps a machine-readable inventory (CycloneDX SBOM) of every open-source component in each deliverable: the backend, the web front end and the on-premises connector agent. SBOMs are generated automatically on every change to the main branch and for every release, including SBOMs of the exact container images, which are attached to the release. Dependencies are scanned continuously: pull requests are checked for vulnerable new dependencies, the front-end tree must pass npm audit at the high level, and release images are blocked if they contain fixable high or critical vulnerabilities; Dependabot proposes updates weekly and security updates immediately, with a 72-hour patch target for critical CVEs. A written licence policy allows permissive licences, allows weak-copyleft libraries only unmodified, requires approval for proprietary or undeclared licences and forbids strong copyleft. The SBOM of version 1.2.0 (278 components across the three deliverables) shows no strong-copyleft component and no known high or critical vulnerability in the front end. Our review on 19 Oct 2026 found that the CI service has been down since 16 Oct and that the automated licence check is not yet enforced; both are scheduled for correction before go-live (evidence SEC-042-E01).
